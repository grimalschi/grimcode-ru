# Шаблон проекта Grimcode

Заготовка продукта, у которой скучная часть уже сделана: публичный сайт, приложение с входом по
логину, админка с правами доступа и почта с редактором писем. Всё это уже работает вместе — дальше
на этой основе делается ваш продукт.

Код пишут и запускают агенты. Вам не нужно ничего программировать: вы описываете, что должно
получиться, а правила, по которым агенты обязаны это делать, лежат в файле `DIRECTIVES.md` — он
ваш, агенты его не меняют.

От вас нужно только подготовить компьютер к запуску и один раз заполнить файл с настройками.

## Что должно стоять на компьютере

| | |
| --- | --- |
| **Docker** | В нём поднимается весь проект. Docker Desktop на Mac и Windows, docker-движок на Linux. |
| **Node 22 или новее** | Нужен для команд запуска и проверок. |
| **pnpm** | Менеджер пакетов. Ставится одной командой: `npm install -g pnpm`. |

## Первый запуск

```bash
pnpm install
```

```bash
cp .env.example .env
```

`.env` — это единственный файл с настройками. Он не хранится в репозитории, потому что у каждого
свой. Значения в нём уже рабочие, но одно стоит поменять сразу:

**`PROJECT_SLUG`** — техническое имя проекта. Из него собираются имена баз данных, поэтому задайте
его в самом начале: если поменять позже, старые базы останутся лежать рядом с новыми.

Остальное можно не трогать. Если порт 63000 на машине уже кем-то занят, сдвиньте диапазон
`PORT_RANGE_START` и `PORT_RANGE_END`, а `GATEWAY_PORT` и `PUBLIC_SITE_URL` приведите к его началу.

```bash
pnpm up
```

Первый запуск займёт несколько минут — Docker собирает образы. Дальше проект поднимается за
несколько секунд.

## Что открывать

Проект живёт по адресу из `PUBLIC_SITE_URL`, по умолчанию http://127.0.0.1:63000

| | |
| --- | --- |
| `/` | сайт |
| `/app/` | приложение, вход и регистрация |
| `/admin` | админка |

**Первый зарегистрированный аккаунт становится владельцем админки.** Зарегистрируйтесь на
`/app/register` и откройте `/admin` — права появятся сами. Дальше владелец раздаёт доступы
остальным.

Проект слушает все сетевые интерфейсы машины, то есть открывается и с телефона, и из виртуальной
машины. Из этого следует одно: пока вы не зарегистрировались, владельцем станет тот, кто сделает
это раньше. В своей сети это неважно, в чужой — зарегистрируйтесь сразу после запуска.

## Базы данных

Локально база — такой же контейнер, как остальное, и живёт она только на вашей машине. Данные в
ней тестовые, их не жалко: можно ломать, чистить и заводить заново.

На боевом сервере база отдельная — её поднимает и обслуживает хостинг или вы сами, а проекту
сообщается только строка подключения `DATABASE_URL`. Проект своей базы там не поднимает, поэтому
случайно перепутать тестовые данные с настоящими нельзя.

Посмотреть, что лежит в базе, можно прямо в админке: раздел **База данных**, доступен только
владельцу.

## Письма

Локально письма никуда не уходят. Всё, что проект отправляет — подтверждение адреса, восстановление
пароля, — остаётся в журнале внутри админки, в разделе **Email**. Там же читаются ссылки, которые
в обычной жизни пришли бы на почту.

Чтобы письма уходили по-настоящему, нужен ключ почтового сервиса — это уже настройка боевого
сервера.

## Работа над несколькими задачами сразу

Если агенты работают над разными задачами одновременно, каждой задаче лучше дать свою копию
проекта. Для этого есть git worktree — отдельная папка со своей веткой:

```bash
git worktree add ../проект-задача -b задача
```

```bash
cd ../проект-задача && pnpm install && pnpm bootstrap:worktree
```

Копия получит свои порты, свою базу данных и свои настройки, а данные из основной копии в неё
перенесутся. Задачи не будут мешать друг другу: сломанное в одной ветке не заденет остальные.

## Команды на каждый день

| | |
| --- | --- |
| `pnpm up` | Поднять проект |
| `pnpm down` | Остановить |
| `pnpm logs <сервис>` | Посмотреть, что происходит внутри одного сервиса |
| `pnpm check` | Проверить код целиком: типы, тесты, сборку, правила проекта |
| `pnpm test:acceptance` | Проверить работающий проект снаружи, как это делает браузер |
| `pnpm test:browser` | То же самое, но настоящим браузером |

Проверки — не формальность: `pnpm check` должен быть зелёным, иначе задача не сделана. Об этом же
сказано агентам в `DIRECTIVES.md`.

## Что внутри

Проект собран из отдельных частей, каждая отвечает за своё:

| | |
| --- | --- |
| **gateway** | Входная дверь: принимает все запросы снаружи и решает, кого куда пускать |
| **site** | Публичные страницы |
| **app** | Приложение за входом: аккаунт, настройки |
| **admin** | Админка: администраторы, права, журнал действий |
| **auth** | Вход, пароли, сессии, восстановление доступа |
| **users** | Профиль пользователя внутри продукта |
| **notifications** | События, из-за которых отправляются письма |
| **email** | Шаблоны писем, редактор и журнал отправки |

Наружу открыт только gateway, остальные доступны лишь изнутри — снаружи к ним не достучаться.
