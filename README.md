# Шаблон проекта Grimcode

Заготовка продукта, у которой скучная часть уже сделана: публичный сайт, приложение с входом по
логину, админка с правами доступа и почта с редактором писем. Всё это уже работает вместе — дальше
на этой основе делается ваш продукт.

Код пишут и запускают агенты. Вам не нужно ничего программировать и не нужно ничего запускать
руками: вы описываете, что должно получиться, а правила, по которым агенты обязаны это делать,
лежат в файле `DIRECTIVES.md` — он ваш, агенты его не меняют.

## Что должно стоять на компьютере

**Docker.** В нём поднимается весь проект. На Mac и Windows это Docker Desktop, на Linux —
docker-движок.

**Node 22 или новее** и менеджер пакетов **pnpm** (ставится через `npm install -g pnpm`).

Больше ничего. Базу данных, веб-сервер и всё остальное проект приносит с собой.

## Первый запуск

Попросите агента запустить проект — он поставит зависимости, подготовит настройки и поднимет
контейнеры. Первый раз это займёт несколько минут: Docker собирает образы. Дальше проект
поднимается за секунды.

Настройки живут в файле `.env`, он создаётся из `.env.example` и не хранится в репозитории, потому
что у каждого свой. Значения там уже рабочие, и единственное, что стоит выбрать в самом начале, —
`PROJECT_SLUG`, техническое имя проекта: из него собираются имена баз данных. Если поменять его
позже, старые базы останутся лежать рядом с новыми.

Второе, о чём агент может спросить, — порты. Проект занимает диапазон, по умолчанию начиная с
63000. Если он на вашей машине уже кем-то занят, диапазон сдвигается — это одна строчка в
настройках.

## Что открывать

Проект живёт по адресу из `PUBLIC_SITE_URL`, по умолчанию http://127.0.0.1:63000

Корень — сайт, `/app/` — приложение со входом и регистрацией, `/admin` — админка.

**Первый зарегистрированный аккаунт становится владельцем админки.** Зарегистрируйтесь в
приложении и откройте админку — права появятся сами. Дальше владелец раздаёт доступы остальным.

Проект слушает все сетевые интерфейсы машины, то есть открывается и с телефона, и из виртуальной
машины. Из этого следует одно: пока вы не зарегистрировались, владельцем станет тот, кто сделает
это раньше. В своей сети это неважно, в чужой — зарегистрируйтесь сразу после запуска.

## Базы данных

Локально база — такой же контейнер, как всё остальное, и живёт она только на вашей машине. Данные
в ней тестовые, их не жалко: можно ломать, чистить и заводить заново.

На боевом сервере база отдельная — её поднимает и обслуживает хостинг или вы сами, а проекту
сообщается только строка подключения. Своей базы он там не поднимает, поэтому перепутать тестовые
данные с настоящими нельзя.

Посмотреть, что лежит в базе, можно прямо в админке: раздел **База данных**, он доступен только
владельцу.

## Письма

Локально письма никуда не уходят. Всё, что проект отправляет — подтверждение адреса,
восстановление пароля, — остаётся в журнале внутри админки, в разделе **Email**. Там же читаются
ссылки, которые в обычной жизни пришли бы на почту.

Чтобы письма уходили по-настоящему, нужен ключ почтового сервиса. Это уже настройка боевого
сервера.

## Работа над несколькими задачами сразу

Каждой задаче лучше давать свою копию проекта — отдельную папку со своей веткой, своими портами и
своей базой данных. Тогда агенты работают параллельно и не мешают друг другу: сломанное в одной
ветке не заденет остальные, а данные для работы в новую копию переносятся из основной.

Заводит такие копии тоже агент, попросите его об этом.

## Что внутри

Проект собран из отдельных частей, каждая отвечает за своё.

**gateway** — входная дверь: принимает все запросы снаружи и решает, кого куда пускать.
**site** — публичные страницы. **app** — приложение за входом: аккаунт и настройки.
**admin** — админка: администраторы, права, журнал действий. **auth** — вход, пароли, сессии,
восстановление доступа. **users** — профиль пользователя внутри продукта.
**notifications** — события, из-за которых отправляются письма. **email** — шаблоны писем,
редактор и журнал отправки.

Наружу открыт только gateway, до остальных снаружи не достучаться.

## Куда смотреть дальше

`DIRECTIVES.md` — ваши правила проекта. Пишете их только вы, агенты обязаны им следовать и должны
сказать вам, если задача им противоречит.

[`docs/`](docs/README.md) — подробное описание устройства проекта. Написано для агентов и для тех,
кто читает код.

`AGENTS.md` — с чего агенту начинать работу над проектом.
