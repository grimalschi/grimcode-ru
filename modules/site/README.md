# site

The public pages, rendered on the server.

Everything here is meant to be read and indexed, so the HTML is complete before any JavaScript runs
— a crawler, a link preview and a slow connection all get the finished page.

It has no database and holds no session. It is not the product; the product is [app](../app).

## Pages

| | |
| --- | --- |
| `/` | Landing |
| `/about` | What this is |
| `/contact` | How to reach the people behind it |
| `/legal/terms`, `/legal/privacy` | Structure with placeholders — see below |
| anything else | A real 404, not a soft 200 |

Metadata lives in the root route, so a page that forgets to describe itself still has a title, a
description and a favicon.

## The legal pages are not legal texts

They ship as a structure: numbered sections, each a heading with a note about what belongs in it.
Real terms and a real privacy policy have to be written for the actual product and its jurisdiction,
and no template can do that.

Both are marked `noindex` and kept out of the sitemap, so a placeholder is never indexed as if it
were an agreement. Remove that once they say something.

## robots.txt and sitemap.xml

Generated by the server rather than shipped as files, because both have to name the site's real
address and that is only known once a deployment sets `PUBLIC_SITE_URL`. See
[`server/index.mjs`](server/index.mjs).

The sitemap lists only what is genuinely public. The application and the admin panel are behind
sign-in, and the legal placeholders have nothing to offer, so none of them appear.

## How it is served

The framework's build produces a fetch handler for the pages and a directory of client files. A
small Node entry serves the static files first, then hands anything that is not a file to the
handler. Hashed bundles are cached for a year; files that keep their names, briefly.

## Commands

```bash
pnpm --filter @template/site dev
```
